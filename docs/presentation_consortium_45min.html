10
The honest caveat

The discrimination is good. The threshold is not.

An AUROC near 0.9 says the model ranks cases well. It says nothing about where the decision threshold sits — and ours sits in the wrong place.

On the challenge set

Recall 0.486 at specificity 0.991. The model misses about half the cancers, while almost never raising a false alarm. It is tuned to be quiet, not to be safe.

On Duke

Recall 0.662 at specificity 0.976. The same pattern, reproduced independently on a cohort from another continent.

This is fixable without retraining. Moving the threshold trades specificity for recall along a curve the model already supports. What it needs is a clinical decision about the acceptable false-positive rate — which is a consortium question, not an engineering one, and we would like to put it on an agenda.

Why 99 % means nothing there

888 of 896 cases have no lesion. A model answering "no lesion" every time scores 99 % and finds no cancer at all.

It has already misled us

Utrecht was described as underperforming on an average across three classes where one class had two cases. Set it aside and Utrecht moves 0.602 → 0.717, Cambridge 0.710 → 0.908.

None of this reflects on any hospital's data. Every figure now travels with the counts behind it, and we no longer rank centres on an average where a class has a handful of cases.

Deliverable D3.2 · M48

Active learning: the model can pick what to label next

Labelling breast MRI is the scarce resource. If the model can point at the cases worth a radiologist's time, the same budget buys more.

Labelling budgetRandom selectionModel-guided (entropy)Gain
10 cases2.4 ± 1.352.1×

40 cases8.9 ± 2.3141.6×
100 cases22.2 ± 2.821—

Malignant cases found within each budget, from a pool of 165 containing 37. Beats random at 5 of 8 budgets, loses at none.

Roughly double, where it counts

At small budgets — the regime where a labelling budget actually binds — model-guided selection finds about twice as many cancers as picking at random.

And where it stops helping

By 100 of 165 cases you have taken most of the pool, so every method converges. The advantage must disappear there; we report it rather than stopping the chart early.

What this does not yet show. No model has been retrained on the selected cases. This measures which cases get picked, not what a model learns from them — that is the next run, and it is the question D3.2 finally has to answer.

Deliverable T3.3 · M54

Differential privacy: the guarantee is now a number

Until now we could say the design protects data. We can now say by how much, on the scale regulators use — and what it costs.

Privacy guarantee (ε)Noise required (σ)Reading
ε ≤ 102.4Weak but not vacuous; widely accepted in practice
ε ≤ 36.7Strong
ε ≤ 118.1Strictest commonly cited; likely destroys utility at this scale

Over a 20-round run at δ = 10−5. Rényi-DP accounting, implemented in-tree because Opacus is not in the ODELIA image.

What it protects

Client-level: an observer of the shared model cannot tell whether a given hospital took part in a round.

What it does not

It says nothing about whether a given patient was in a hospital's data. That needs noise during local training, and we are not claiming it.

This is now a consortium decision, not a default. More noise buys a stronger guarantee and costs accuracy. The cost is not yet measured — one training run at σ = 2.4 turns this table into a real trade-off.

Deliverable D3.4 · M48

Adversarial robustness: the textbook defence is wrong for us

The exposure is real

Every job combines contributions by a plain weighted average, which has no bound at all. Measured: Barcelona — 190 volumes, 0.6 % of the data — can drag the shared model 5.5× its own size away from the truth. Being small is not being harmless.

The standard fix backfires

Robust aggregators work by discarding unusual contributions. They cannot use dataset weights — so they aim at the average site instead of the pooled data. With Aachen holding 83.9 % of benign cases, those are very different targets.

Aggregation ruleError with no attackerKeeps dataset weights?
Weighted average (current)0.023Yes — but no protection at all
Norm-bounded average0.032Yes
Trimmed mean0.466No
Coordinate median0.600No
Krum0.639No — keeps one site's update
Recommendation: bound each contribution, keep everyone. It holds the same attack to 0.04 at almost no cost. The limit must be stated too — bounding is proportional to weight, so it does not stop the majority contributor. Capping any one site's share is a governance decision with a real accuracy cost.

Milestone MS6 · M54

White-hat attack: we started without waiting

The proposal schedules the white-hat exercise between partners, and that is still how the full exercise should run. But a scheduling round-trip is not a reason to have measured nothing, so we ran the part we can run alone.

The question we attacked
An observer sees only the model's three output probabilities for a case — no identifier. Can they work out which hospital it came from? This matters because per-case predictions are exactly what we are proposing to move between sites.
Cases testednAttacker accuracyChanceVerdict
No-lesion cases only1110.1850.192No leak
Malignant cases only330.6040.317Leaks

Balanced accuracy against a permutation null, p = 0.007. Restricted to hospitals with at least 5 malignant cases, because averaging recall over a site with one case is meaningless.

On malignant cases the shared model is site-identifiable — among three hospitals an observer names the right one 60 % of the time against 33 % chance. On no-lesion cases there is nothing. So it is not simply case mix; the model behaves differently per site on the cases that matter clinically.
This is a lower bound, not the exercise. Our attacker gets three numbers; a real one sees the weights. It is not membership inference and not reconstruction. MS6 still needs Cambridge and Radboud, as the proposal says — this tells us what to look for when we get there.
